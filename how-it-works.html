How CityMind Turns a Research Question into a Structured Brief

By Peng Jing · Updated August 2026

CityMind currently uses a structured single-stage prompt. The prompt defines the role, evidence boundaries, output order and writing style before requesting one complete research brief.

Step 1: Define the research scope

The user enters a focused research topic, study area, use scenario, target reader, output language and any available materials. A focused question is more useful than a broad keyword.

Step 2: Set content and evidence rules

The system prompt tells the model not to invent exact statistics, policy clauses, citations, case names or measured results. When evidence is missing, the output should label the point as a hypothesis, data gap or item requiring verification.

Step 3: Generate a fixed output structure

  1. Topic interpretation
  2. Executive summary
  3. Research framework
  4. Key findings or preliminary hypotheses
  5. Policy, industry and spatial dimensions
  6. Presentation outline
  7. Data gaps and verification list
  8. Next research tasks
  9. Accuracy and use notice

Step 4: Verify before formal use

Users should check every policy, statistic, case, date and citation against an original source. Generated content is a starting point for research, not verified evidence.

Why the project does not claim two-stage generation yet

The planned next version will first create a machine-readable outline, validate it for repetition and missing sections, expand each section separately and then assemble the final brief. That process will only be described as “implemented” after the code is complete.

Current implementation: structured single-stage prompt.
Planned iteration: outline JSON → validation → section expansion → final assembly.

What is recorded for content iteration

  • Prompt version and test date;
  • Research topic and user scenario;
  • Missing, generic or repeated sections;
  • Unverified claims or invented details;
  • User feedback and resulting prompt changes.
